Infrastructure & Architecture

System Architecture Overview

Technology stack, component responsibilities, and inter-service communication paths across the full platform.

⚛️

Frontend — React SPA

Single-page application built with React 18 + Vite. Features client-side protected routing using AuthContext, role-based UI (admin vs. user), animated parallax layout, and a modular component library.

React 18ViteFramer Motion React Router v6Context API
⚡

Backend — FastAPI Service

Python FastAPI application serving 12+ REST endpoints for auth, predictions, PDF parsing, and admin operations. JWT-based OAuth2 flow with bcrypt password hashing and role-level middleware guards.

FastAPI 0.110UvicornPython-JOSE Passlib/bcryptSQLAlchemyAlembic
🧠

ML Service Layer

Scikit-Learn models loaded via Joblib at startup. Four dedicated prediction functions (diabetes, heart, hypertension, CBC) with a shared get_prediction_insights() helper returning class, probability, and algorithm name.

Scikit-LearnJoblibPandas NumPy4× .pkl files
🗄️

Database — MySQL 8

Relational MySQL database with 6 core tables: users, patient_reports, heart_reports, hypertension_reports, cbc_reports, verification_codes. Foreign key relationships with ON DELETE SET NULL cascade behavior.

MySQL 8mysql-connector-python PyMySQLAlembic migrations
📄

Document Processing

PDF report ingestion via pdfplumber with regex-based CBC value extraction. Pytesseract OCR integration for image-based lab report parsing. Uploaded files stored in local uploads/ directory.

pdfplumberpytesseract PillowLocal storage
🔐

Auth & Access Control

OAuth2 password flow with JWT tokens (24-hour expiry). Two role levels: user and admin. Pydantic input validation, email normalization, mobile number sanitization. OTP-based password reset (console-printed, not SMS-sent).

JWT (HS256)bcrypt OAuth2BearerPydantic v2

Security Analysis

Security & Vulnerability Assessment

Authentication, data protection, API exposure, and authorization posture review based on direct source code analysis.

🔑 Authentication

  • JWT tokens (HS256) issued on login
  • bcrypt + pbkdf2_sha256 password hashing
  • OAuth2PasswordBearer scheme enforced
  • SECRET_KEY hardcoded as plain string
  • Token expiry set to 24 hours (too long)
  • No token refresh mechanism implemented
  • OTP sent to console, not via SMS

🛡️ Authorization

  • Role-based access: user / admin
  • Admin guard via get_current_admin()
  • Protected routes in React frontend
  • /ml-studio route has NO auth protection
  • Admin checks email string contains "admin"
  • No rate limiting on any endpoint
  • No brute-force protection on /token

🔒 Data Security

  • Passwords never stored in plaintext
  • Pydantic validates all request data types
  • SQL queries use parameterized statements
  • No HTTPS/TLS (HTTP only in dev)
  • DB password defaults to empty string
  • Medical data stored without field-level encryption
  • Uploaded files not scanned for malware

⚠️ Data Quality Issues Found

  • Glucose=0, BloodPressure=0 pass validation (physiologically impossible)
  • CBC reports stored as raw JSON blobs — no structured querying
  • OTP codes never purged from verification_codes table
  • No DB indexes on user_id foreign keys — full table scans at scale
  • ML imputer uses mean strategy — can distort predictions with 0-values

✅ Data Strengths

  • All passwords bcrypt-hashed before storage
  • Parameterized queries throughout — no SQL injection risk
  • ON DELETE SET NULL prevents orphaned report data
  • Email uniqueness enforced at DB level (UNIQUE constraint)
  • JSON columns for conditions/specialists allow flexible schema extension
  • updated_at timestamp auto-maintained on user records

📤 File Storage

  • Uploads stored in local backend/uploads/ directory
  • No file type validation beyond extension check
  • No file size limit enforced
  • No soft-delete or cleanup job for uploaded PDFs
  • Filenames from user input — path traversal risk if sanitized incorrectly
  • Recommendation: migrate to cloud blob storage (S3/GCS)

Risk & Issue Identification

All Audit Findings

12 issues identified across security, performance, data, and ML domains — categorized by severity with impact analysis.

🔴 Critical (2)
CriticalHardcoded JWT Secret Key
The JWT signing secret is a plain, predictable string in auth.py. Any attacker can forge tokens for any user account including admin. Impact: Full system compromise.
Criticalerror_log.json Exposes Internal Errors
A 30KB JSON error log file is committed to the repository, potentially exposing DB schema, stack traces, and internal path information publicly. Impact: Information disclosure.
🟠 High (4)
HighML Studio Unauthenticated Access
The /ml-studio route has no <ProtectedRoute> wrapper, allowing any anonymous user to access the ML training interface and upload arbitrary CSV data.
HighNo Rate Limiting on Auth Endpoints
The /token (login) and /register endpoints have no rate limiting. Brute-force password attacks and automated account creation are unrestricted.
HighAdmin Query Performance Degradation
The /reports/admin endpoint executes 4+ sequential non-indexed queries. At scale (100+ users), this will cause severe latency or timeouts. No pagination implemented.
HighDiabetes Recall 68.4% — Clinical Risk
Nearly 1-in-3 actual diabetic patients are predicted as negative (false negative). For a clinical screening tool, this recall level is a patient safety risk.
🟡 Medium (6)
MediumNo Input Range Validation at ML Layer
Physiologically impossible values (Glucose=0, WBC=0) pass directly into ML models, silently degrading prediction accuracy.
MediumNo HTTPS / TLS Configuration
All API communication is HTTP-only. Patient health data transmitted over the network is unencrypted and vulnerable to interception.
MediumNo ML Model Versioning
Static .pkl files with no version metadata or training provenance. Silent model regressions impossible to detect without full re-audit.
MediumOTP Delivery Console-Only
The password reset OTP is printed to server console, not delivered via SMS. Completely non-functional in a real deployment scenario.
MediumFile Upload Without Size/Type Limits
No maximum file size, MIME type validation, or malware scanning on uploaded PDF/image files. Potential for DoS via large uploads.
MediumNo Prediction Audit Trail
ML predictions are not systematically logged with input features, enabling no post-hoc review, bias analysis, or regulatory audit capability.

Final Conclusion

Audit Verdict

Overall Rating: Approved for Academic Demo

Health Analyzer v2.0 demonstrates a well-architected, clinically-aware MVP with thoughtful ML integration, transparent confidence reporting, and a clean full-stack structure. The platform is suitable for academic presentation and portfolio demonstration.

However, two critical security vulnerabilities (hardcoded JWT secret, unprotected ML Studio), combined with the absence of HTTPS, data-at-rest encryption, and GDPR compliance mechanisms, make the system unsuitable for production clinical deployment in its current state. Completing R-01 through R-06 (estimated 1–2 days of work) would significantly elevate the security posture for a supervised pilot deployment.
